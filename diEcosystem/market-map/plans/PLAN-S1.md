5. **Tick-object / recorder policy -- SETTLED DECISION (owner, 2026-08-30): dedicated scalar trace bus.** `EventBus._capture` stores the payload **by reference** (`EventBus.js:333`) and `replay()` re-emits those stored references (`EventBus.js:415-`). Recording the live object `tick` channel is therefore incompatible with S2's reused-scratch decode: every ring slot would alias the one scratch object and replay would redraw a flat line at the last price -- silently (the count still reads N). Resolution, applied from S1 onward and inherited by S2:
   - The live `bus` (object `tick`/`trade` fan-out) is **NOT recorded**. `parseFrame` may reuse per-tag scratch freely (S2), because `BookApply`/`TapeApply`/`AggApply` consume synchronously inside the emit.
   - Add a second, recording-only `traceBus = new EventBus(c)` that carries **numbers only**: on each accepted tick, after the object fan-out, `traceBus.emit('mid', t.mid)` (a scalar). `traceBus.record(RING, {onOverflow: 'drop-oldest'})`; `handle.replay()` calls `traceBus.replay()`, whose single `'mid'` handler repaints the price trace from the scalar.
   - Why a *dedicated* bus, not a scalar channel on `bus`: `record()` captures the whole bus (no per-channel filter -- signature is `record(capacity, opts)`, `opts` only carries `onOverflow`), and a payloads array that only ever holds doubles stays an unboxed double-elements array in V8 -- so each capture is an inline store with **no per-tick HeapNumber boxing**. Emitting the scalar onto the shared object bus would both re-capture the aliased objects AND risk boxing the double into a tagged-pointer array.
   - Monomorphism / SoA / object-pool were evaluated and rejected for this seam: monomorphism is orthogonal to the reference-lifetime bug; an SoA/pool ring is honest and zero-GC but is demo-owned and would drop the event-bus flight-recorder showcase. The scalar trace bus is the only option that is zero-GC AND honest AND keeps `bus.record`/`replay` as the showcased mechanism.
   - The sim generator (task 3) emits into the same seam: it feeds `emitTick(t)` for the live object channel and the trace scalar identically, so sim and wire share one honest recorder. Record this decision + the three rejected alternatives in the rationale (seed for Session 7's ledger).

## 5. RISKS / OPEN

1. **Published-vs-local versions.** Local `package.json` versions are *not* proof of an npm publish. If any of the 15 is unpublished at that version, the pinned map 404s and the demo is dead on arrival -- worse than unpinned. Coder must `npm view` each before writing the map, and the assertion is "every pinned URL returns 200".
2. **`lite-gl@2.0.0` is a major bump** vs whatever `latest` the page floats to today. Pinning may change point/quad sink behaviour. Verify the GPU path visually at zoom 3.0 *before* committing the pin; if it regresses, pin the last known-good 1.x and record why.
3. **Sim tick allocation (task 5) -- RESOLVED.** Owner chose the dedicated scalar `traceBus`: live `bus` reuses scratch (zero-alloc), the recorder captures only numbers (zero-alloc, unboxed doubles), replay stays honest, and the event-bus flight-recorder showcase is kept. No event-bus change needed. Remaining coder note: `traceBus` is a second `EventBus(c)` binding -- register it in `bootKernel` and wire its teardown (`onTeardown` -> `dispose()`) so the 50x churn / shutdown gates stay clean.
4. **`FailoverJob` timing** -- cron `tickMs` is 1000 (kernel.js:439), so "~4 s" is 4-5 s, which slips past a strict 3 s gate for the *degraded* first frame. Either accept "first frame <= 3 s, degraded frame <= 5.5 s" (recommended; the 3 s gate is about the page rendering, and the 2D canvas paints grid + empty trace immediately), or shorten the watchdog to 2 samples at 500 ms via a dedicated cron. Owner picks.
5. **`sim://` is not a real scheme** -- if anything downstream ever hands `feedUrl` to `new URL()` or `createSocket`, it throws. Task 4's branch must be the *only* consumer; verify `setSource`'s log line at kernel.js:529 (`url.replace(/^wss?:\/\//,'')`) still reads sensibly for `sim://random-walk`.
6. **Pages path** -- publishing the whole repo exposes all packages; publishing the `diEcosystem/` subtree breaks the relative `./kernel.js` unless the subtree root is chosen correctly. Owner decides scope; the import map is esm.sh so no `node_modules` needs shipping either way.
