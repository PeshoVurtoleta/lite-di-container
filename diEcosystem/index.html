The thesis

One core. Everything else is a binding.

Every capability is built on the container, not beside it: its units are container-constructed classes with injected dependencies, cached at boot, and torn down in reverse-topological order. No sibling reaches into another's internals — they compose through the graph.

The container shipped invalidate / rebind at 2.2.0 — post-boot hot-swap. That single hinge is what lets the supervisor rebuild a faulted subtree in place. Rebind is the hinge; the orchestrator is the capstone.

One service lifecycle

From boot to SIGTERM, in order.

The siblings aren't a grab-bag — they map onto the ordered life of one long-running service. That order is real: teardown runs it in reverse.

The reactive plane

Every scope draws itself.

In the market-map demo, one symbol tab is one child scope: one lite-signal registry, one defineReactive view-model fleet (lite-signal-decorators), all disposed together. Because the view-model's members are decorated, the scope can render its own live dependency graph — lite-devtools' toDot({ labelResolver }) with the decorators' labelOf bound to that scope's registry, so every node prints its member name.

The whole kernel exports as one .dot: the lite-di-graph container graph with one subgraph cluster_<symbol> per live scope nested inside it (node ids namespaced per scope so two symbols never collide). The graph is the live topology — a scope that has taken a quote settles at seven reachable reactive nodes.

Why it reads as one product

Eleven packages, one set of laws.

law · dependencies
Zero runtime deps

Every package ships single-file ESM, node:test only, sideEffects: false. The container is a peer, never bundled.

law · allocation
Zero-GC hot paths

Every dispatch, tick, emit, and select measures 0.000 B/op — hard-gated over a million ops, gc major = 0.

law · failure
Fail closed, always

Every unverified state throws with a named cause. An empty lane is not-ready; a lost lease is LOST. null is not zero.

law · shape
DI-native units

Handlers, jobs, systems, listeners — all container-constructed classes with injected deps, torn down in reverse-topological order.

law · proof
Torture or it didn't ship

Proven by node --expose-gc test/torture.mjs (lite-leak + lite-gc-profiler). No gate output is a FAIL.

law · surface
Frozen, then additive

Each 1.0.0 froze an exact export set. Growth is additive minors — event-bus 1.1.0 added record/replay with the nine originals byte-identical.

Not a diagram — a running proof

The whole lifecycle, asserted.

lock, health, supervisor and orchestrator can't be proven in isolation — their reason for being is the ordered, fail-closed life of one service. So the suite ships service-kernel.mjs: a runnable reference app that boots the graph, holds a fencing lease, takes a fault and self-heals, exhausts a restart budget, then catches SIGTERM and drains in the right order.

Every claim is checked with node:assert/strict, and npm run example is a hard prepublish gate. A broken contract exits non-zero.

// asserted teardown order on SIGTERM
drain → supervisor.shutdown → steps → container → exit(OK) once 
// self-heal: a fault rebuilds the subtree in place
oldDb.broken = true;
// health POLLS and sees it; supervisor is PUSH-based
assert.notEqual(health.readyz(), 0);
assert.equal(sup.check(), 0); // not told yet

await sup.run('db', () => c.get('db').query());
// rest-for-one rebuilt db + cache + api
assert.notEqual(c.get('db'), oldDb);
assert.equal(sup.check(), 0); // healed, green

// a HELD lease reaches RELEASED only via
// container-driven dispose() — proving order
assert.equal(leaderLock.state, LOCK.RELEASED);

kernel complete
